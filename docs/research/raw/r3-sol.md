**Verified** means checked against linked primary sources on 2026-11-02. **Deduction** means a counterexample derived from these documents, without runtime testing. **Residual** refers to earlier findings recorded in validation.md. Findings are ranked by consequence.

1. **Residual: SSRF protection still admits local destinations. [Verified + deduction]** The deny table omits `::/128`. Go explicitly treats `[::]:80` as the local system, so a literal implementation would admit `http://[::]/`. Reject unspecified addresses explicitly. Also define proxy handling: a dial check can validate the proxy rather than the ultimate destination. Authenticated feeds need credential stripping across origins, including custom secret headers; IP validation cannot prevent that disclosure. These behaviours are documented in [Go’s networking API](https://go.dev/pkg/net/?m=old#Dial) and [HTTP client documentation](https://pkg.go.dev/net/http#Client).

2. **Residual: the “no agent exit” invariant is not established. [Deduction]** Fixed destinations do not imply confidential payloads: an injected agent can put private content into notification titles sent through push providers. [Apple explicitly advises encrypting sensitive payloads](https://developer.apple.com/documentation/usernotifications/generating-a-remote-notification). More directly, **if `read_entry` invokes on-demand extraction**, selecting an entry selects a feed-author-controlled URL. An attacker can provide different URLs and instruct the agent to encode secrets through its selections. Require cached-only agent reads, audit indirect triggers, and define permitted recipients and payloads. Invariant 1 must explicitly cover internal models: external agents necessarily read feed content while holding Earnest tools.

3. **Residual: restore recovery can repeat irreversible actions. [Deduction]** Take backup B; accept notification operation X; deliver it; lose the response; restore B; replay X. X’s idempotency record and delivery history disappeared, so it can deliver again. Longer retention cannot prevent this: [a PostgreSQL dump restores the state at dump time](https://www.postgresql.org/docs/18/backup-dump.html). Specify how uncertain notifications are reconciled or withheld after restore. Require generation rotation during recovery and bind mutation preconditions to generations: reused register revisions can otherwise falsely match an old `base_rev`. Ordinary delivery-worker crashes also need an explicit duplicate-delivery policy.

4. **Introduced by the replacement: bulk changes cannot be replayed faithfully. [Deduction]** An entry deliberately marked unread at time 20 must survive a delayed mark-all from time 10. The server skips it, but `state.range` contains neither the timestamp, register/value nor effective exceptions needed for clients to reproduce that result. Folder/cluster membership can also change. `through_seq` protects newer entries, not later decisions concerning older entries. Simplest remedy: make ranges invalidations and refetch authoritative cached states, or specify immutable membership and complete merge metadata. Bulk `base_rev` semantics are missing.

5. **Introduced: Google Reader “mark unread” fails on Done items. [Deduction]** Removing `read` sets `seen=unseen` but leaves `shelf=done`; the read predicate still returns true. Starring a Later item also overwrites `later` with `keep`, and unstarring erases that shelf decision. Define these transitions explicitly, including whether starring needs an independent register. Existing-client testing must cover cross-surface round trips, not only endpoint availability.

6. **Introduced: timestamp normalization contradicts its guarantees. [Deduction]** “Never raised” conflicts with replacing old timestamps by receipt time. An ancient offline unread operation can acquire today’s timestamp and defeat yesterday’s deliberate read. Specify a maximum queue age and reject or reconcile expired operations rather than making them newest. A stale `base_rev` also does not prove concurrency: successive actions queued by one offline device can share the same base. Define causal ordering within an outbox.

7. **Residual: bootstrap remains underspecified. [Deduction]** Taking a cursor first can work, but “idempotent by revision” alone does not define how snapshot rows, older replay events and pending local writes interact. Require stable pagination, object-revision comparisons, cache replacement rules, complete resource coverage and handling of entries deleted before their bodies are fetched. Bootstrap currently omits annotations and labels. These details determine test expectations.

8. **Residual: the rule-action boundary remains ambiguous. [Deduction]** `label=press_release AND feed=X` satisfies the deterministic-term requirement while leaving the classifier in control of whether the action fires. The documents acknowledge this input weakness, but do not consistently specify its consequences: the safety table promises undoable actions, notification rules are irreversible, and tier 3 requires “deterministic matches” without defining whether mixed label/keyword predicates qualify. Define permitted predicate types per action tier, and separate agent-written labels from classifier labels.

9. **The NewsBlur uncertainty is factually outdated. [Verified]** Its [README explicitly documents self-hosted MCP](https://github.com/samuelclay/NewsBlur/blob/main/README.md#self-hosted-mcp-server); [Docker settings expose AI-provider keys and Ask AI/briefing model selection](https://github.com/samuelclay/NewsBlur/blob/main/newsblur_web/docker_local_settings.py). Replace “isn’t stated” with “documented, not runtime-tested.” **Trying NewsBlur first is appropriate as a bounded adoption test. [Judgement]** Test the actual NAS deployment and clients. Its [advertised MCP includes subscription changes and public sharing](https://www.newsblur.com/features/mcp), so step 0 needs an enforced tool allowlist.

10. **The sequence still postpones essential decisions. [Judgement]** Put a minimal executable state/protocol model and its vectors before schema/API commitment; step 2 should validate independently specified expectations. Keep compatibility clients as the initial reading surface. Define the minimum brief workflow before step 5: entry-bound annotations need a convention for storing and displaying a multi-entry brief. MCP also promises hybrid search/clustering that arrive at step 9; specify initial fallbacks. Reading a brief daily tests brief usefulness, not demand for distinct agent identities. Hiding counts tests count preference, not decay or closure.

11. **Claims still overconfident. [Judgement / textual contradictions]** Remove “without … lasting damage or leak anything,” High confidence in the current sync protocol, “Reeder … can’t desync,” and universal undo in UX principle 5. Product availability does not prove cadences beneficial or mandatory table stakes. “No strong market case” and one supposedly open gap exceed the demand research performed. The 40–55-week estimate remains unsupported anchoring; present it as one scenario with explicit scope assumptions.

**Replacement sync model: NO, not yet sufficient for unambiguous conformance vectors.** Resolve findings 3–7 first. The counterexamples above can become design tests, but several expected outcomes still require decisions.

**“No agent exit” as stated: NO.** It needs a bounded threat model and explicit treatment of indirect fetching and notification payloads.

**Verdict: NO.** Minimum before implementation: specify bulk/conflict/bootstrap/restore behaviour, repair compatibility transitions, close the outbound-policy gaps, replace the absolute no-leak guarantee, and correct the NewsBlur evidence and sequence dependencies.
